# Git Commit Rules (コミットメッセージ規約)

本ルールは、リポジトリのコミット履歴を美しく、追跡可能に保つための規約です。

---

## 1. 適用範囲
- **対象**: ステージングされた変更（`git diff --cached`）のみを対象とします。未ステージングの変更や未追跡ファイルは無視します。
- ステージングされた変更がない場合、コミットメッセージの生成を行わず、ユーザーにステージングを促してください。

## 2. Conventional Commits 形式の厳守
すべてのコミットメッセージは、以下のフォーマットに完全に従わなければなりません。

```
<type>[optional scope]: <description>

[optional body]

[optional footer(s)]
```

### Type一覧（常に小文字・英語）
- `feat`: 新機能の追加
- `fix`: バグの修正
- `docs`: ドキュメントの変更のみ
- `style`: コードの動作に影響しない見た目の変更（スペース、フォーマット、セミコロンなど）
- `refactor`: バグ修正や新機能追加を含まないコードのリファクタリング
- `perf`: パフォーマンスを向上させる変更
- `test`: テストコードの追加・修正
- `build`: ビルドシステムや外部依存関係の変更 (例: npm, pip)
- `ci`: CI設定やスクリプトの変更
- `chore`: その他の動作に影響しない雑多な変更 (例: .gitignore, LICENSE)

### Description (件名)
- 最大 **50文字以内** で簡潔に記述。
- 末尾にピリオド（`.`）を付けない。
- 言語はユーザーの指定に従うこと（指示がない場合は原則英語、明示的な場合は日本語）。

### Body (本文・任意)
- 件名と本文の間には必ず空行を1行挟む。
- 変更の「理由」「背景」「影響」を論理的かつ簡潔に記述。

---

## 3. Guardrails (禁止事項)
- ❌ **絵文字（Emoji）**の使用は一切禁止。
- ❌ **スラングや曖昧な口語表現**の禁止。
- ❌ **以下の曖昧な単語のみのコミットメッセージは厳禁**:
  - `update`, `fix`, `change`, `modify`, `更新`, `修正`, `変更`, `対応`, `wip`
  - 何をどのように更新・対応したのかを具体的に記述すること。
- ❌ **出力時の余計なメタ解説の禁止**:
  - メッセージ生成時は「コミットメッセージの本文のみ」を出力し、前後の「こちらがコミットメッセージです」などの解説テキストは一切省くこと。
