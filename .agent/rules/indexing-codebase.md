# Project Structure Awareness (プロジェクト構造認識)

本ルールは、エージェントがプロジェクト全体の構造や依存関係を推測ではなく、確実な事実に基づいて把握し、ハルシネーションを極小化するための手順です。

---

## 1. Index Before Act (行動前にインデックスを取る)
- 新しいタスク、リファクタリング、あるいは調査を開始する際、**必ず最初にプロジェクト構造の全体像を把握する**。脳内推測だけでコードを書き始めない。
- **具体的な調査手段:**
  - `list_dir` や `grep_search` を用いて、関係するディレクトリツリーやエントリーポイント（フロントエンドの `App.tsx` やバックエンドの `main.py`）を確実に特定する。
  - 技術スタックの構成、ドメイン境界、レイヤリングルールを把握してからコードの設計に入る。

## 2. Grep, Don't Guess (推測せず検索する)
- **原則:** 存在しない関数、クラス、型定義、あるいはライブラリモジュールを捏造しない。
- **具体的な調査手段:**
  - 確証がないコードや設定を変更・追加する際は、必ず `grep_search`（ripgrep）を実行して、既存の定義や呼び出し方法の実例を確認する。
  - 変更を加えるファイルの **Forward（参照先）** と **Reverse（被参照元）** の双方向の依存関係を意識し、影響範囲をすべて洗い出してから編集する。

## 3. Verify After Change (変更後に検証する)
- ファイルを新規作成、削除、リネームした後は、古いファイル名やパスへのインポート参照が残っていないかを `grep_search` で徹底的にスキャン・検証する。
- 関連するコード変更を行った後は、コードのコンパイル（TypeScriptのビルド）やテストが通るかを検証し、デグレーションを防ぐ。
